## 1. Install / remove / status semantics per provider (source-backed)

## 4. Async permission/trust branches and file-generation guards (explicit)

1. **Codex trust** is part of install/status, async and lane-serialized: `grantManagedCodexHookTrust` RPC against a codex app-server session (verified re-list hashes) with a self-computed fallback under `ORCA_DISABLE_CODEX_TRUST_RPC`; grant is awaited during install; status treats stale/missing/disabled `[hooks.state]` keys as `partial`. WSL lane runs grants **inside** the distro; canonical-path settlement async (`reconcileSettledWslCanonicalPath`) repairs or revokes trust after launch. Config `config.toml` files are mutated under `runExclusivelyFor*TrustConfig` mutual-exclusion lanes.
2. **Grok generation guards**: sync `install()` re-reads raw bytes before `rename` and refuses (`error: 'Grok hook config changed during installation'`); `removeAsync()` holds the live file aside (`<path>.<pid>.<uuid>.held`) and only commits via exclusive-create when bytes are unchanged, restoring the held file on race; Windows owner token release waits on liveness with `hasRegisteredGrokHookOwner` before committing; symlink configs are written through, never unlinked, with a cleanup marker.
3. **Claude statusLine**: slot-level user-vs-managed-vs-empty with an install marker (`claude-statusline.installed`); marker write best-effort (catch); `preserveMode` and content-identical write skipping prevent rewriting/backup-rotation churn.
4. **Legacy Codex representations**: `~/.codex/hooks.json` and `orca-agent-status.config.toml` profile block removed only when the managed command/token is present, with `preserveMode:true` and pre-write byte guards.

## 5. Local vs remote host/OS ownership

- All `installRemote` flows are **SFTP-backed, POSIX-only**, and never derive remote script syntax from the local OS (comments in claude L256-258, gemini L255, cursor L238-239, devin L198-199, hermes, kimi, remote installer header). Remote writes are atomic temp+rename with 10s SFTP timeouts; config mode preserved or 0o600; scripts 0o755.
- Remote `.bak` is intentionally **not** created (`installer-utils-remote.ts` L44-47).
- **Status/ownership is local-user-global**: owner is `homedir()/$HOME`/`%APPDATA%`/env homes, not a selected SSH runtime and not profile-private state (matches lead's S4-hooks oracle assertion).
- Remote caps: claude remote omits statusLine (L286-288); gemini remote mirror must byte-match local; kimi/command-code/devin/copilot remote are POSIX `.sh` always.
- Missing capabilities (explicit): remote **Windows** hook targets are out of scope everywhere (POSIX-only SFTP); only local hosts run the win32 `.cmd`/PowerShell/codepen chains. AmpHookService has no real runtime result (agent.ts plugin) assertion here; hermes `is_visible_to_real_cli` test depends on `hermes` binary presence.
