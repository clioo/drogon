## Three-level runtime contract

Use installed official `orca-cli`, `orchestration` and `mentu-navigator` skills. Root dispatches the five leads through Orca Task/Dispatch; each lead may create a child Run bound to its own terminal only if nesting is allowed. Creating a Run never resets worker depth. A lead must not spoof root identity, settle early or use a generic subagent tool to escape `nested_worker_depth_exceeded`.

Begin with one lead/model/depth smoke. If the injected live context allows child dispatch, execute one bounded child task, verify source evidence and lifecycle settlement/release. Expand to five leads after confirming Astra launches correctly; do not block their own audit work on unavailable child depth. Initial ceiling: five leads plus one leaf per lead, not an unrestricted recursive swarm. Further leaf fan-out requires root to allocate non-overlapping writes and confirm provider capacity.

Within each owned directory the lead owns `report.md` and `closure.json`; its leaf may write only `leaf/`. Leaves do not edit lead outputs or delegate. Lead must review leaf claims, handle questions, settle/release all children, and only then send its own `worker_done`. Root receives the candidate, independently reviews, and releases or reassigns that exact lead. Timeout is not failure; poll the existing handle instead of restarting.

Permissions are per invocation: Codex CLI's verified equivalent is `--dangerously-bypass-approvals-and-sandbox`; Claude/AGY use `--dangerously-skip-permissions`; installed OpenCode uses `--auto`. These never expand file ownership or permit destructive actions. Preserve explicit denies and do not change global defaults. AGY remains on hold unless quota recovery is verified. Pi + DGX Spark remains reserved for real test inference and the controlled Mentu comparison.
