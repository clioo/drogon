### S2-schedule: Cron and RRULE validation and occurrence search

- Ownership: pure caller-side validation and local Date arithmetic; this is not a remote scheduler execution guarantee. S1 automations create/update validate before destination mutation, but earlier target resolution may already perform RPCs; destination ordering is not a zero-prior-RPC guarantee.
- parseSchedule trims and chooses RRULE whenever the string contains =. RRULE splits semicolon entries then =, uppercases keys only, ignores unknown fields and lets the last duplicate key win. FREQ must exactly be HOURLY, DAILY or WEEKLY; BYHOUR defaults 9 and BYMINUTE 0, both Number-coerced then integer/range checked (0..23, 0..59). Weekly BYDAY is a nonempty comma list of exact SU/MO/TU/WE/TH/FR/SA with no token trimming; daily/hourly do not validate or use BYDAY.
- Cron rejects expressions over 2048 UTF-8 bytes before tokenization, admits the explicitly enumerated Unicode whitespace classes, and requires five fields. UTF-16 length short-circuits oversize; UTF-8 measurement pairs only in-bounds surrogate pairs, counts lone surrogates as three bytes, and stops strictly above the byte limit.
- Each cron field supports comma unions, inclusive ranges and at most one slash with integer step >=1. Empty components, malformed ranges, reversed/out-of-bounds endpoints and invalid names throw. Number coercion admits numeric spellings beyond plain decimal; month and weekday names are case-insensitive. Bounds are minute 0..59/hour 0..23/day 1..31/month 1..12/weekday 0..7, with Sunday 7 normalized to 0. A singleton/step is still a singleton. Restricted day flags derive from expanded set sizes, not the original star spelling.
- Month must match; day-of-month/day-of-week use OR when both restricted, otherwise AND. isValid* catches parse errors and rejects cron with no possible matching date over nine leap-year-sized years; date possibility does not independently inspect time fields. RRULE validity only parses. Cron-only validator rejects RRULE.
- Preset builders floor/clamp hour, minute and weekday (weekday default Monday); hourly omits BYHOUR, weekdays uses fixed MO,TU,WE,TH,FR order. parseAutomationRrule recognizes that exact ordered weekday list, otherwise weekly must have one day; tryParse returns null on unsupported presets.
- Next occurrence is strictly after afterMs and >=dtstart; cron starts at minute floor and scans at most 9*366 days of minutes. Latest is <=now and >=dtstart, returns null when now<dtstart/no candidate. Hourly aligns minute then advances/backtracks one hour. Daily/weekly iterate local calendar candidates with fixed DAY_MS increments and finite 370-day searches. DST, invalid timestamps and scan exhaustion require explicit fixtures; no timezone conversion is supplied here.
