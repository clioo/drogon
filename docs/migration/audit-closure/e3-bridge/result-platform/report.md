**Material findings and corrections.**

1. **Cloud cancel is not discard-only.** [Mobile cancel](/Users/carlos/Documents/Drogon-mentu-session/src/main/runtime/runtime-mobile-dictation-controller.ts:119) calls the same `stopDictation` as finish. [Cloud stop](/Users/carlos/Documents/Drogon-mentu-session/src/main/speech/stt-session-stop.ts:24) calls `session.finish()`, which [combines buffered audio, clears chunks and performs multipart POST](/Users/carlos/Documents/Drogon-mentu-session/src/main/speech/openai-transcription-client.ts:107). `feedAudio` buffers locally at 16 kHz with a 600-second limit; it does not stream HTTP per chunk. Cloud stop converts provider failure into a sink error; finish checks recorded errors, cancel does not. A matching cancel can therefore submit buffered audio and still return only `{dictationId}`. The fetch implementation supplies no abort signal or timeout. This is an as-is characterization; a discard-only cancellation requirement needs a separate root-approved correction and discriminating test.

2. **The speech deletion fallback is reachable.** The leaf's statement that `voice_model_delete_failed` is unreachable is rejected. [The mapper](/Users/carlos/Documents/Drogon-mentu-session/src/main/speech/speech-model-deletion.ts:38) returns null for generic errors; [the RPC-adjacent catalog](/Users/carlos/Documents/Drogon-mentu-session/src/main/runtime/runtime-mobile-speech-catalog.ts:62) uses the fallback. Filesystem removal, worker termination or settings writes can fail. The original deletion assertion body explicitly rejects a synthetic `permission denied` error and verifies settings remain unchanged. Sequential removals can partly complete; a subsequent list can reject after successful deletion.

3. **A computer action can succeed at the call boundary without verified UI effect.** [Desktop result rendering](/Users/carlos/Documents/Drogon-mentu-session/src/main/computer/desktop-script-snapshot-rendering.ts:7) can return a valid accessibility snapshot with `screenshot:null` and `screenshotStatus.state:'failed'`. [Set-value verification](/Users/carlos/Documents/Drogon-mentu-session/src/main/computer/desktop-script-action.ts:122) returns `unverified/value_mismatch` or `provider_unavailable` without throwing. Native JSON-lines results are passed through after protocol admission rather than fully validated against result schemas. Timeout means **unverifiable effect**, not proof no input occurred.

4. **Android gesture and rotation have distinct limitations.** [Android input implementation](/Users/carlos/Documents/Drogon-mentu-session/src/main/emulator/android/android-input-commands.ts:40) reduces a gesture to its endpoints at a fixed 300 ms duration; intermediate points are ignored. Rotation first disables auto-rotation, then writes orientation, so the second command may fail after the first effect. [APK installation](/Users/carlos/Documents/Drogon-mentu-session/src/main/emulator/android/android-capability-operations.ts:15) rejects `Failure|Error` in stdout/stderr even with exit code 0. Android AX parses a synthetic root with required children and omitted empty/invalid attributes; logcat returns either parsed timestamp/level/tag/message or message-only fallback. iOS install, launch, permissions and logcat are explicitly unsupported.

5. **Automation launch acknowledgment is not completed work.** The [actual serve-mode dispatcher](/Users/carlos/Documents/Drogon-mentu-session/src/main/startup/main-process-automations.ts:22) creates a worktree or launches a terminal, then returns a separate completion promise. It waits for `tui-idle`, reads the last 2,000 lines, and projects completed/dispatch_failed plus a bounded optional output snapshot. Creation can leave a workspace before a missing startup terminal raises an error. Owner/target resolution may already issue RPCs before later context/destination validation. Cross-owner `DR-TERMINAL_METHODS` (`terminal.read`, `terminal.wait`) and `DR-WORKTREE_METHODS` (`worktree.create`, `worktree.show`) remain the other leads' result obligations.
