**TOML and path outcomes.** The scanner tracks multiline basic/literal strings and array depth; it is not a full TOML validator. Key paths require valid quoted/bare segments and table-header full consumption. The separate project-header decoder preserves unknown escapes, unlike the value decoder, so escaped Unicode project spellings can yield different lookup identities. See AR-C01 and [src/main/codex/config-toml-syntax.ts:1–179](/Users/carlos/Documents/Drogon-mentu-session/src/main/codex/config-toml-syntax.ts:1).

The trust-level extractor applies a raw multiline regex to the whole block: a trust-looking line inside a multiline string can affect classification. `extractOrdinaryCodexSettings` actually retains untrusted project blocks despite its drop-every-project comment. These are source-inferred characteristics needing explicit characterization and correction tests, not reasons to drop trust scope.
