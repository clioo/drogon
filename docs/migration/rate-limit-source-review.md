## Reproduced source defect: RATE-QUEUE-001

A forced Codex-only cycle is pending. A forced full refresh and another forced Codex refresh queue behind it. Once the first Codex and then the full cycle resolve, the initiating call returns, but `codexOnlyFetchQueued` remains true and both queued callers still wait. In `fetchCodexOnly`, `shouldContinue` was set false before the full-cycle branch's `continue`; the next iteration never drains the remaining flag. `resolveFetchIdleWaiters` consequently does not resolve those callers. The test verifies that stop subsequently clears them. This is a concrete controlled interleaving, not a claim that every refresh or every real provider triggers it.
