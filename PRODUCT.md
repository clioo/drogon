# Product

## Register

product

## Users

Developers and maintainers coordinating coding agents across repository worktrees, ordinary folders and remote execution hosts. They need to continue real work, review changes and see what an agent actually did without losing terminal context.

## Product Purpose

Drogon is an independent desktop workspace and CLI for harness-backed sessions, persistent Bots and session-native Mentu workflows. The rewrite must preserve useful Orca behavior while establishing Drogon's own execution core. Success means a real task can be launched, supervised, recovered and verified through Drogon itself.

## Brand Personality

Quiet, direct, dependable. Preserve Orca's established monochrome visual system rather than inventing a new application aesthetic. Game of Thrones character presets belong to Bot identity, not decorative chrome; any redistributed artwork needs verified rights.

## Anti-references

- A wholesale visual redesign of Orca.
- Verbose forms explaining internal architecture before users can act.
- Copying Hermes screen-for-screen rather than its minimalist principle.
- Decorative dashboards, fake activity, simulated success or green badges without evidence.

## Design Principles

1. Keep the working session central: workspace navigation left, terminal/work surface center, contextual tools right.
2. Mentu belongs inside a session: right panel and a wider tab through `+` share the same selected recipe, draft and run state.
3. Bots own identity, chat, skills, harness and responsibilities; a Bot is not the same entity as a Mentu execution. Reactive triggers are deterministic; proactive reasoning happens after a scheduled wakeup.
4. Prefer useful defaults and progressive disclosure. A preloaded character supplies its name and avatar; custom name is optional. Advanced configuration should not obstruct creation.
5. Report observed state honestly. Missing providers, pending migrations, failed tests and unreachable hosts need actionable recovery, not success language.

## Accessibility & Inclusion

Preserve the source style guide's keyboard navigation, visible focus, correct platform shortcut labels, focus stability under remote latency and reduced-motion behavior. Keep controls labeled, semantic states distinct and error text visible. The inherited design tokens and primitives remain the starting point; verify readable contrast in both themes. No accessibility certification is claimed.

## Source of these decisions

The approved rewrite plan, user-confirmed Bot/Mentu UX requirements and the previous implementation's `docs/STYLEGUIDE.md` and handoff. This is a product-context record, not evidence that the rewritten UI already exists.
