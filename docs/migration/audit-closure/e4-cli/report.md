## How to review the complete mapping

`command-map.json.commands` contains exactly one row for each accepted canonical command. Each row retains the catalog source/hash, aliases, hidden/destructive metadata, declared flags and positionals. Its handler points to a function or factory binding, with start/end lines and file SHA-256. `observableContract` links literal RPC calls (including parameter and timeout expressions), flag reads, formatter/output calls, explicit exit assignments, error-bearing helper nodes and host routing. `semanticNodes` retains variable bindings/default expressions, conditions, calls, throws, returns, assignments and helper references. Factory arguments remain explicit: for example `checkHandler(true)` versus `checkHandler(false)`, and the Linear add/remove relation factory. A shared helper's alternative branches are a conservative lexical association; they are not all reachable on every invocation.

The extractor joins the accepted catalog to actual exported handler records, expands orchestration record spreads, checks each manifest group's keys against its exports, rejects duplicate keys and asserts all 234 spec hashes still match the reference. It does not import or evaluate source modules. Existing installed Babel is used through the desktop's dependency graph; nothing was installed. The extractor resolves named CLI functions but does not evaluate dynamic imports, object methods, closure argument specialization or non-CLI implementation bodies. It is not scope-aware: shadowed and property identifiers can overassociate a helper. Those limits are explicit, not inferred missing commands. Root independently flagged this distinction, and the open disposition preserves it.

Thirty `acceptedContract` links point to the existing coordinator-reviewed evidence. No representative sample is substituted for the other 204 rows. `flagRouting` classifies every declared flag's lexical connection; literal appearance is a discovery check, **not proof of a flag's required/default/type semantics**. The three dynamically constructed stdin flag names are manually reconciled below, and the five obsolete coordinator-start flag names are accepted syntax with an unconditional retirement error. Their absence from active reads is intentional.

## Shared CLI rules that must survive the rewrite

`flags.ts:6-145`: required strings reject non-string and zero length but do not trim; allowing-empty variants accept `''`; optional strings turn empty/non-string into undefined. Optional numeric flags likewise treat non-string/empty as absent, convert with `Number`, reject nonfinite values and then apply the named positive/nonnegative integer restriction. Nullable numeric accepts exact `null`. `getOptionalJsonFlag` detects quote-stripped JSON shapes but returns the raw string; downstream code still owns actual JSON parsing. Repeated strings split the parser's NUL separator and remove empty entries. These helpers differ from artifacts' trimmed string helpers and from orchestration's strict positive-safe-integer timeout parser.

`format.ts:70-189`: ordinary `printResult` emits the full success envelope as pretty JSON (with the computer-result preparation hook), or the supplied result formatter as text. RPC failure envelopes are preserved; local errors become `{id:'local',ok:false,error:{code,message,data?},_meta:{runtimeId:null}}` on stdout in JSON mode. Text errors go to stderr. Runtime-unavailable errors add launch guidance except when mutation-recovery identity already supplies recovery instructions; automation-owner conflicts retain their specific classification/recovery. `index.ts:177-180` sets exit 1 for caught command/flag/transport errors. The legacy CLI does not share Drogon's usage-exit-2 rule.

`index.ts:29-43,111-176` and `execution-host-flag.ts:23-218`: account/artifacts/environment/host/serve/agent/vm/agent-context suppress pairing/environment routing. This does **not** mean every one rejects every explicit selector: account and artifacts reject retarget flags; host/environment listings reject them; environment show/rm use `--environment` as a local store selector; other local families may simply ignore routing. Global value-shape validation still runs first. `--host runtime:<name-or-id>` resolves the caller's pairing store, canonicalizes to its ID, rejects contradictory explicit pairing or different explicit/ambient environment, and outranks ambient pairing. `ssh:` resolves against the connected runtime's SSH registry. Runtime host filters also match that server's `local` records. Neither axis is a guessed local fallback.

`selectors.ts:29-360`: local current/active resolution chooses the longest enclosing managed path and returns the concrete ID; remote current/active rejects client-cwd inference. Browser commands use explicit page IDs globally, optionally validate explicit worktree, otherwise infer local cwd with catch-all no-filter fallback; remote omission leaves server-side selection to the runtime. Computer session/worktree are mutually exclusive and `app` remains required. Emulator targeting additionally preserves `ORCA_WORKTREE_ID` and `folder:` `ORCA_WORKSPACE_ID`; explicit device/emulator does not discard the selected workspace. WSL spelling conversion requires caller/root evidence, preserves unmatched selectors and is not applied to remote client paths. File and emulator install paths must remain on their execution host.

`runtime/client.ts:70-343`: default RPC timeout is 60,000 ms, not the stale 15-second comment in a browser handler. Explicit call timeouts override it; terminal wait and waiting orchestration check extend positive inner budgets by 10,000 ms with the default as a floor. Worker-start uses its separate safe timer budget. Orchestration mutations preflight contract capability, mint/reuse a request identity and attach original-command recovery on transport failure. Remote transport preflights protocol compatibility, preserves the exact selected pairing host, and marks the selected environment's verified runtime identity (`runtime/remote-runtime-compat-gate.ts:23-92`). An unverified connection does not prove process exit. Preserve `live` / `unverifiable` / `exited` as separate verdicts.
