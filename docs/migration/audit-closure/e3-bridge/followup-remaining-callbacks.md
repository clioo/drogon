## Material corrections and state boundaries

- **Update cancellation replies immediately.** `skills:cancelUpdateRun` invokes synchronous `cancel()`; the process sweep continues asynchronously. The 12-second fallback may restore `idle` without proving descendants exited. Report liveness as `live` / `unverifiable` / `exited` from actual evidence.
- **Update success can lack a rescan verdict.** A rejected rescan falls back to the exit result; zero exit becomes success. The existing rescan-failure test also emits a spawn error, so it does not assert this zero-exit branch. A degraded alias can also disappear from the convergent topology filter.
- **The leaf's duplicate/refinement claims required correction.** Prepare IDs are collapsed through a Set; duplicates normally succeed when every distinct ID resolves. Bundle install and preview IPC schemas copy `.shape` fields and lose the shared whole-object uniqueness/subset refinements. The local full install request parser restores them later; that is a distinct admission boundary.
- **Cloud declarations are not response validation.** Successful HTTP JSON is cast to the declared type; invalid JSON becomes `null`, 204 becomes `undefined`, and delete responses can carry JSON under HTTP 200 despite a `void` annotation. Resolve/share-grant calls are explicitly unauthenticated and normally return `ok` or throw, rather than producing the declared auth-status alternatives.
- **Skills HTTP auth errors use the wrong class for the shared refresh predicate.** `SkillCloudRequestError` 401/403 is not an `OrcaCloudRequestError`, so that operation error bypasses the wrapper's refresh/reconnect retry path. This is a source-derived defect, not an executed reproduction.
- **Explicit outer `ssh:` environment and SSH destination are different paths.** The former bypasses the IPC transfer controller yet still reaches remote environment installation inside the grant installer; cancel selects the local runtime map. The latter, with no outer environment, correctly uses runtime destination routing and its controller. Cancellation during grant authorization also precedes controller registration.
- **Cancellation and failed results do not promise rollback.** A canonical install can remain committed with partial provider placement after cancellation. Bundles commit skills sequentially; some errors outside the per-skill catch can reject after earlier commits. `removeInstall` with a `cancel` conflict choice can still remove clean owned content. A failed discovery verification reports failure while leaving transaction results on disk.
- **Deletion rechecks before the lock, not under it.** Host roots, path containment and displayed mtime are inspected when rebuilding the plan, but the delete transaction does not recheck freshness immediately after acquiring its lock. Duplicate requested IDs/paths are accepted, and local results are not reparsed through the exported bounded output schemas.
- **Trust varies by family.** Skills requires the exact trusted live renderer object; TCC requires the captured live main renderer; focus callbacks require exact sender identity. Seven window callbacks have no sender gate, with only the close receipt checking sender ID. Browser viewport reporting has a configured-ID or origin fallback plus downstream page ownership and finite nonnegative metric checks; the earlier syntax-only concern about absent viewport validation was incomplete.
- **Observation failures are not always distinguishable from absence.** Managed receipt listing can return an empty list on directory failure and `missing` on observation failure; some preview/recovery lstat helpers collapse errors to absence. WSL discovery can return partial enrichment, and prepare subsequently packages through native Node filesystem paths without a WSL-aware copier in this call chain.

These findings describe the original source. The rewrite must not silently claim stronger safety, validation, atomicity or parity from annotations or mocks; root owns any decision to change defective behavior.
